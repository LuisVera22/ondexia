# Caché NVD en reintentos de CI y CD

Base `b0fc4a5`, develop. El reintento exitoso del CI #305 descargó 403.375 registros y generó informes. Después falló el guardado: `Unable to reserve cache with key nvd-37867279154`. La clave ya existía con la copia del intento fallido. Guardar una caché no acreditaba una base completa; no se asume reanudación incremental de una descarga inicial interrumpida.

## Corrección

Clave completa con identificadores de ejecución e intento en ambos workflows. Se guarda únicamente si se generó `apps/backend/target/dependency-check-report.html`, incluso si un hallazgo hace fallar el análisis. Se priorizan copias completas frente a respaldo heredado `nvd-`. Descarga abortada o análisis omitido sin informe no genera una copia etiquetada como completa. El workspace de los jobs es nuevo; los targets no se restauran desde estas cachés.

La auditoría continúa activa; no cambia el umbral CVSS ni se omite la actualización NVD. Pruebas de la política ejecutadas por CI y CD con Python estándar, sin dependencias adicionales.

## Verificación

Cuatro pruebas, cada una contrasta ambos workflows. Antes del arreglo: seis fallos de aserción; después: cuatro pruebas correctas. Escenarios independientes: caché inmutable, dos intentos de una ejecución, descarga sin informe, análisis con informe y copia incompleta más reciente que una completa. Mutación aislada de la clave de guardado: detectada y restaurada; paso final correcto. YAML válido y diff sin errores.

El primer borrador del lector de pasos tenía una expresión regular demasiado amplia. Sus errores de preparación se descartaron; se corrigió el lector y se volvió a probar sobre los workflows originales para obtener el fallo funcional válido conservado aquí.

## Límites

La caché reduce descargas iniciales repetidas; no las elimina en ramas sin copia accesible, expulsión de cachés o cambio incompatible de formato. La actualización de vulnerabilidades vigente se mantiene. Las pruebas locales modelan la caché inmutable y contrastan las condiciones configuradas; no certifican el servicio GitHub. Pendiente verificar guardado y restauración reales con las nuevas claves. No se ejecutó CD, no se desplegó AWS y no hay auditoría independiente nueva. No se repiten pruebas de negocio: no cambia código funcional.
